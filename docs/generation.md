# Генерация

Сборка одного источника идёт в фиксированном порядке.

1. Читается `docloom.yml`. Если файла нет, конфигурация обнаруживается по дереву. См. [конфигурацию](configuration.md).
2. Гайды: `SUMMARY.md`, затем Markdown из каталога `sources.guides`.
3. `README.md` в корне становится первой страницей руководств, если гайды его ещё не содержат.
4. Python: обход `*.py` под каждым корнем из `sources.python`, разбор `ast`.
5. OpenAPI 3: по странице на каждую операцию.
6. Если есть предупреждения — страница диагностики.
7. Склейка `SUMMARY`: руководства, справочник Python (методы на страницу класса ссылаются со страницы класса и в меню отдельно не висят), справочник HTTP, служебное.

Повторный прогон на тех же файлах даёт тот же Markdown. В текст страниц время сборки не подставляется. Имена вроде `__init__` проходят через экранирование `_` и `*`, поэтому Markdown не съедает их в заголовках и подписях ссылок.

## Python

Импорта и исполнения нет. Публичными считаются имена без одного ведущего `_`. Из дандеров в справочник входит `__init__`. Модуль и каталог, чьё имя начинается с `_`, пропускаются. `__init__.py` остаётся страницей пакета.

Если в модуле есть `__all__` из строковых литералов, в справочник модуля попадают эти функции и классы. Имена из `__all__`, которых в файле нет, перечисляются как повторный экспорт.

Страница символа содержит сигнатуру, docstring, таблицу параметров (без `self` и `cls`), аннотацию возврата и путь `файл:строка`. Символ без docstring остаётся в книге и получает предупреждение `missing_docstring`. Файл с синтаксической ошибкой сборку не роняет: предупреждение `syntax_error`, остальные файлы обрабатываются.

## OpenAPI

Принимается спецификация с полем `openapi`, начинающимся на `3.`. Методы: `get`, `post`, `put`, `patch`, `delete`, `head`, `options`, `trace`. На странице — summary, `operationId`, параметры, тело, ответы с примерами и требования security. Ссылки `$ref` показываются как есть, компоненты целиком не разворачиваются.

Битый YAML, корень не объект, версия не 3.x или отсутствие `paths` дают `invalid_openapi`. Операций из этого файла нет, остальные источники собираются.

## Коды предупреждений

| Код | Откуда |
| --- | --- |
| `missing_summary` | нет `SUMMARY.md`, гайды идут в порядке обхода |
| `unlisted_guide` | файл в каталоге гайдов не упомянут в summary |
| `missing_guide` | ссылка summary ведёт на отсутствующий файл |
| `external_summary_link` | ссылка summary наружу, страницей не стала |
| `missing_python_root` | каталог из `sources.python` отсутствует |
| `missing_docstring` | модуль, класс, функция или метод без docstring |
| `syntax_error` | файл Python не разобрался |
| `unreadable_file` | файл Python не прочитался |
| `missing_openapi` | путь спецификации отсутствует |
| `invalid_openapi` | спецификация не стала набором операций |

Пустой каталог `src/` и сломанный OpenAPI вместе дают `success_with_warnings`. Страница диагностики попадает в раздел «Служебное».

## Статусы книги

| Статус | Когда |
| --- | --- |
| `success` | Предупреждений нет |
| `success_with_warnings` | Книга собрана, диагностика есть |
| `failed` | Исходник не прочитан: путь вне allowlist, git не сделал checkout, у Bitbucket нет ни одного файла книги, у проекта нет источника |

`failed` каталог версии не публикует. SHA такого билда в базе пустой, поэтому опрос на следующем интервале ставит задачу снова.

## Отпечаток исходника

Для `local_path` в `build.json` пишется SHA-256 содержимого файлов: путь и байты в стабильном порядке. Каталоги `.git` и `__pycache__`, а также файлы `*.pyc`, в отпечаток не входят. Для `git_url` пишется SHA коммита после checkout указанной ветки или тега. Глубина клона — 1. `ref` передаётся аргументом `git`. Таймаут clone и fetch — 300 секунд.

Адрес Bitbucket вида `/scm/{проект}/{репозиторий}.git` при непустом токене клоном не качается: SHA берётся через `git ls-remote` (не дольше 60 секунд), файлы книги — через REST. Подробности в [Bitbucket](bitbucket.md).
