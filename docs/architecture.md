# Архитектура

Источник истины — файлы ревизии. Один и тот же каталог при тех же байтах даёт тот же Markdown справочника. Справочник Python строится разбором `ast`. Команды сборки из yaml не запускаются.

```
источник (local_path, git clone или файлы Bitbucket)
        │
        ▼
   API (FastAPI) ── очередь в SQLite
        ▲
        │  watch ставит билд, когда сменился SHA
        ▼
   worker
        │  config → extract → weave → HTML
        ▼
   /publish/{проект}/{версия}/
        │
        ▼
   nginx :8080  →  /sites/…, /health, /api, /hooks
```

`watch` и `POST /hooks/git` только ставят задачу. Книгу пишет worker. При `DOCLOOM_SYNC_BUILDS=1` тот же код сборки выполняется внутри процесса, который принял запрос. В compose это выключено.

## Сервисы Compose

| Сервис | Процесс | Роль |
| --- | --- | --- |
| `api` | `docloom serve` | Проекты, постановка билдов, webhook, `/health` |
| `worker` | `docloom worker` | Забирает очередь и пишет книгу на диск |
| `watch` | `docloom watch` | Опрашивает одну ветку и ставит билд при новом SHA |
| `nginx` | nginx 1.27 | Раздаёт опубликованные сайты и проксирует API |
| `test` | `pytest` | Профиль `test`, в обычный `up` не входит |

Образ у `api`, `worker` и `watch` один: `docloom:0.1.0`. Redis в MVP нет. Очередь и метаданные — файл `docloom.sqlite` на томе `data`.

Процесс `docloom` в контейнере работает от uid 10001. Точка входа при старте от root создаёт каталоги томов и отдаёт управление этому пользователю. Повторный старт уже от uid 10001 каталоги заново не создаёт.

Heartbeat worker пишется в `/data/worker-heartbeat`, проверка compose считает процесс живым, пока файлу меньше 30 секунд. Heartbeat watch — `/data/watch-heartbeat`, порог 180 секунд: интервал опроса по умолчанию 60 секунд, и проверка не должна падать между циклами.

## Тома

| Том | Путь в контейнере | Содержимое |
| --- | --- | --- |
| `data` | `/data` | SQLite, логи билдов, heartbeat worker и watch |
| `publish` | `/publish` | Готовый HTML, его же читает nginx как `/sites/` |
| `sources` | `/sources` | Клоны и выгрузки файлов, если у проекта задан `git_url` |

Образ дополнительно содержит `/opt/docloom/samples` — каталог демо. `local_path` принимается, если после `resolve` он лежит внутри одного из корней `DOCLOOM_SOURCE_ROOTS`. В compose это `/opt/docloom/samples` и `/sources`.

Каталог выгрузки для git-проекта: `/sources/{имя проекта}/{версия}`. Повторный билд той же версии обновляет этот каталог.

## Пара (проект, версия)

Worker берёт самый старый `queued`, у которого для той же пары нет статуса `running`. Другая версия того же проекта может собираться одновременно. Один процесс worker выполняет одну задачу за раз. Пока билд в `queued` или `running`, `watch` новую задачу на ту же версию не ставит.

Имя версии получается из `ref`: префиксы `refs/heads/` и `refs/tags/` снимаются, пустое имя и `HEAD` становятся `latest`. В имени допустимы буквы, цифры, точка, подчёркивание и дефис, длина от 1 до 100 символов. `.` и `..` отклоняются. Слэш в имени версии не принимается, поэтому ветка `feature/login` в версию не превращается.

Успешный билд пишет строку в таблицу `versions`. Имя `latest` помечается версией по умолчанию. Неуспешный билд каталог версии не публикует и SHA в базе не оставляет: следующий опрос может поставить сборку снова.

## Сеть

Снаружи открыт только порт `8080`. API слушает `8000` внутри сети compose. Nginx резолвит имя `api` через DNS Docker (`127.0.0.11`) на каждый запрос, поэтому пересоздание контейнера API не оставляет прокси со старым адресом.

Статика `/sites/` читается с тома `publish`. Отсутствующий файл внутри версии отдаёт `404.html` этой версии со статусом 404. Ответы `/api/` и `/hooks/` этот обработчик не подменяет.

`worker` и `watch` получают `extra_hosts` из `DOCLOOM_EXTRA_HOST` (`имя:адрес`). Это нужно, когда имя Git-сервера из контейнера не резолвится. API к Git не ходит и эту запись не использует.
