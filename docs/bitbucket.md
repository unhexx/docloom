# Автосборка из Bitbucket

Пользователь ничего не нажимает. Есть два входа, оба ставят тот же билд, и книгу пишет worker.

Рабочий путь, когда Bitbucket не открывает адрес Docloom, — опрос. Webhook остаётся для случая, когда сервер Git сам достучится до `POST /hooks/git`.

## Опрос

Сервис `watch` в compose раз в `DOCLOOM_WATCH_INTERVAL` секунд (по умолчанию 60, минимум 15) спрашивает удалённую ветку.

1. `git ls-remote` возвращает SHA. Запрос идёт по HTTP/1.1, не дольше 60 секунд.
2. Проект ищется по clone URL. Совпадают адреса без пользователя в URL, без суффикса `.git` и с именем хоста в нижнем регистре. Если проекта нет, он создаётся: имя — последний сегмент пути, не длиннее 80 символов.
3. Активный билд этой версии (`queued` или `running`) новый запуск пропускает.
4. SHA последнего успешного билда (`success` или `success_with_warnings`) сравнивается с удалённым. Совпало — очередь не растёт.
5. Иначе в очередь попадает билд без заранее записанного SHA. SHA сохраняется, когда сборка завершилась успешно.

Неуспешный билд SHA не сохраняет. Следующий опрос ставит сборку снова. Тот же коммит после успеха повторно не ставится. Новый коммит запускает сборку сам. Старый успешный коммит можно пересобрать через `POST /api/projects/{id}/builds`.

В `.env` (файл не коммитится, образец — [`.env.example`](../.env.example)):

```env
DOCLOOM_WATCH_URL=https://git.example.com/scm/PROJ/repo.git
DOCLOOM_WATCH_REF=master
DOCLOOM_WATCH_INTERVAL=60
DOCLOOM_GIT_TOKEN=
DOCLOOM_GIT_SSL_VERIFY=1
DOCLOOM_EXTRA_HOST=git.example.com:203.0.113.10
```

`DOCLOOM_GIT_TOKEN` — HTTP access token Bitbucket. Он уходит заголовком `Authorization: Bearer`, в URL не попадает и вырезается из текста ошибок. `DOCLOOM_GIT_SSL_VERIFY=0` нужен, когда сертификат сервера выписан на другое имя: и `git`, и запросы REST перестают проверять сертификат.

`DOCLOOM_EXTRA_HOST` пишет `имя:адрес` в `/etc/hosts` контейнеров `watch` и `worker`. Так ходят к серверу, чьё имя не резолвится из Docker. После смены URL, токена или этой записи:

```bash
docker compose up -d --force-recreate watch worker
```

Один проход без демона: `docloom watch --once`. Пустой `DOCLOOM_WATCH_URL` оставляет процесс живым и билдов не ставит. Ошибка опроса печатается в лог сервиса и следующий интервал пробует снова.

Если в репозитории нет `docloom.yml`, книга всё равно собирается: `README.md`, каталог `docs/` и `openapi.yaml`, когда они есть. Свой `docloom.yml` перекрывает этот набор.

## Какие файлы забираются с Bitbucket

Полный `git clone` адреса `https://сервер/scm/ПРОЕКТ/репозиторий.git` при непустом токене не выполняется: pack на таком сервере часто останавливается после сжатия объектов. Вместо клона:

1. Список файлов: `GET /rest/api/1.0/projects/{KEY}/repos/{slug}/files` (ключ проекта в верхнем регистре, страницы по 200).
2. Содержимое нужных путей: `GET /rest/api/1.0/projects/{KEY}/repos/{slug}/raw/{path}?at=refs/heads/{ветка}`. Сегменты пути кодируются по отдельности, слэши остаются разделителями.

В книгу попадают только:

| Путь | Условие |
| --- | --- |
| `README.md`, `SUMMARY.md`, `docloom.yml` | имя в корне, регистр не важен |
| `openapi.yaml`, `openapi.yml` | имя в корне |
| `docs/**/*.md` | любой Markdown под `docs/` |
| `src/**/*.py` | Python под `src/` |

Если ни одного такого файла нет, сборка падает с текстом «в ревизии нет README, docs или docloom.yml». Другие git-адреса, включая локальный `file://`, по-прежнему клонируются неглубоко (`--depth 1`), таймаут 300 секунд. Тот же таймаут у fetch повторного билда. REST-выгрузка включается только когда одновременно задан токен и путь содержит `/scm/{проект}/{slug}.git`.

`git` всегда стартует с `http.version=HTTP/1.1`. При `DOCLOOM_GIT_SSL_VERIFY=0` добавляется `http.sslVerify=false`.

## Сменить репозиторий

Опрос смотрит на один URL. Чтобы следить за другим репозиторием, поменяйте `DOCLOOM_WATCH_URL` и `DOCLOOM_WATCH_REF` в `.env` и пересоздайте `watch` и `worker`, как в команде выше. Проект в базе появится сам при первом успешном опросе. Старый сайт на диске остаётся, пока его каталог в томе `publish` не удалят отдельно.

`docloom.yml` в чужой репозиторий класть не требуется.

## Webhook

Bitbucket Server / Data Center, репозиторий → Webhooks → Add webhook.

| Поле | Значение |
| --- | --- |
| URL | `http://<хост-docloom>:8080/hooks/git` |
| События | `repo:refs_changed` |
| Secret | тот же, что `DOCLOOM_WEBHOOK_SECRET` или `webhook_secret` проекта |

Docloom принимает облачный payload Bitbucket (`push.changes`) и серверный (`eventKey: repo:refs_changed`). Проект ищется по clone URL, затем по slug или имени. Удаление ветки и `toHash` из сорока нулей сборку не ставят. Другой `eventKey` отвечает `ignored` и тоже сборку не ставит.

Подпись сверяется по `X-Hub-Signature` или `X-Hub-Signature-256`, оба в виде `sha256=` и HMAC-SHA256 сырого тела. Секрет проекта, если он задан, важнее секрета окружения.

Webhook сработает, когда Bitbucket открывает этот URL. Если Docloom стоит во внутренней сети и сервер Git до него не доходит, соединение должно исходить от Docloom: это опрос.
